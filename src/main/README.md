# 🚀 QA-Core: Tracker & Notification Microservice

Автономный бэкенд-микросервис на **Kotlin** для управления задачами (Kanban) и баг-репортами (Bug Lifecycle). Сервис поддерживает авторизацию по токенам, работу с базой данных, хранение медиафайлов/документов и асинхронную интеграцию с Telegram-ботом.

---

## 📐 Архитектура системы
Проект спроектирован как изолированный **микросервис** с REST API:
* **Веб-сервер:** Ktor Server (REST API, JSON, Multipart FormData).
* **Безопасность:** Авторизация на базе JWT (JSON Web Tokens).
* **База данных:** JetBrains Exposed ORM + H2 / PostgreSQL.
* **Бизнес-логика:** Двойной домен — Канбан-доска для задач + Конечный автомат (State Machine) для жизненного цикла багов.
* **Интеграция:** Асинхронный клиент Ktor Client для отправки Multipart-уведомлений (с файлами) в Telegram API.

## 🛠️ Стек технологий
* **Язык:** Kotlin (JVM)
* **Фреймворк сервера:** Ktor Server (Routing, JWT Auth, ContentNegotiation)
* **Асинхронность:** Kotlin Coroutines
* **Работа с БД:** JetBrains Exposed ORM + H2 (для тестов) / PostgreSQL (для продакшена)
* **Сетевой клиент:** Ktor Client
* **Тестирование:** JUnit 5 / Kotest

## 📋 Функциональные возможности (Features)
1. **JWT Authentication:** Доступ к созданию и изменению задач/багов имеют только авторизованные пользователи по токену в заголовке `Authorization: Bearer <token>`.
2. **Канбан для Задач:** Четкое движение тасок по колонкам (`BACKLOG` ➡️ `TODO` ➡️ `IN_PROGRESS` ➡️ `DONE`).
3. **Жизненный цикл Багов:** Строгая валидация статусов баг-репорта (нельзя закрыть баг без проверки).
4. **Медиа-хранилище:** Загрузка и привязка к сущностям скриншотов (`.png`, `.jpg`) и документов (`.pdf`, `.docx`). Файлы переименовываются в `UUID` для исключения конфликтов имён.
5. **Telegram Bot Dispatcher:** Асинхронный пуш критических событий напрямую в Telegram-канал команды вместе со всеми прикрепленными к багу файлами.
